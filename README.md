# exfortables_py

`exfortables_py` is an EXFORTABLES-inspired collection of observable-based
datasets derived from the
[EXFOR library](https://www-nds.iaea.org/exfor/). It turns the entry-oriented
content in [IAEA-NDS/exfor_json](https://github.com/IAEA-NDS/exfor_json) into
files organized by projectile, target nuclide, reaction, and observable.

The pointwise datasets provide analysis-ready `(x, dx, y, dy)` tables.
Observable summaries and resonance-parameter files use additional,
observable-specific columns. Every file retains EXFOR provenance in a
human-readable header.

The datasets are generated by
[IAEA-NDS/exforparser](https://github.com/IAEA-NDS/exforparser) and are used by
the [IAEA Nuclear Reaction Data Explorer](https://nds.iaea.org/dataexplorer/)
and its [REST API](https://nds.iaea.org/dataexplorer/api/).

> [!IMPORTANT]
> This repository is under active development. Directory names, selection
> rules, and table formats may change as the parser and Data Explorer evolve.

## Data provenance

The data flow is:

```text
EXFOR master entry (.x4)
        |
        v
exforparser
        |
        v
exfor_json entry
        |
        |-- merge entry and subentry COMMON/DATA blocks
        |-- select reaction pointer and observable
        |-- normalize units and derive uncertainties
        v
exfortables_py text tables
        |
        |-- IAEA Data Explorer plots and downloads
        `-- IAEA Data Explorer Reactions API
```

The original EXFOR records are maintained in
[IAEA-NDS/exfor_master](https://github.com/IAEA-NDS/exfor_master). The
entry-level JSON representation is published in
[IAEA-NDS/exfor_json](https://github.com/IAEA-NDS/exfor_json). The
`exforparser` tabulation code is the single source of truth for observable
selection, unit conversion, directory placement, and output formatting in this
repository.

Dataset updates record the corresponding EXFOR master release in their commit
messages. To identify the snapshot in a checkout, run:

```sh
git log -1 --format=%s
```

## Download

Clone the complete repository with:

```sh
git clone https://github.com/IAEA-NDS/exfortables_py.git
```

The dataset contains a large number of files. A shallow clone avoids
downloading its complete history:

```sh
git clone --depth 1 https://github.com/IAEA-NDS/exfortables_py.git
```

To retrieve only part of the tree, use sparse checkout. For example, to
download neutron-induced data for Al-27:

```sh
git clone --depth 1 --filter=blob:none --sparse \
  https://github.com/IAEA-NDS/exfortables_py.git
cd exfortables_py
git sparse-checkout set n/Al-27
```

## Dataset structure

Most data use this layout:

```text
<projectile>/<target>/<reaction>/<observable>/<file>.txt
```

For example:

```text
n/Al-27/n-inl-L1/xs/
n/U-234/n-f/fission/yield/independent/
n/Zn-66/n-el/resonance_parameter/WID/G/
```

Heavy-ion and other multi-character projectiles use a target-first `ion`
layout:

```text
ion/<target>/<projectile>/<outgoing-channel>/<observable>/<file>.txt
```

For example:

```text
ion/Zn-66/C-12/non/xs/
```

The principal path components are:

- **Projectile:** `n`, `p`, `d`, `t`, `a`, `h`, `g`, `e`, `0`,
  pion codes, or the unified `ion` tree. `0` denotes a spontaneous process.
- **Target:** an element and mass number such as `Al-27`. Natural elemental
  composition uses mass `0`, for example `Ag-0`.
- **Reaction:** a filesystem form of the EXFOR process, such as `n-g`,
  `n-tot`, or `n-inl-L1`. A suffix such as `L1` denotes a discrete level.
- **Observable:** the selected data product. Some observables add another
  classification directory.

Observable directories currently include:

| Directory | Observable |
| --- | --- |
| `xs` | Cross section |
| `angle` | Angular distribution |
| `energy` | Energy distribution |
| `energy/angle` | Double-differential distribution |
| `fission/yield/<type>` | Fission yield, classified by yield type |
| `neutrons` | Neutron-production observables |
| `thermal` | Thermal neutron cross section |
| `macs` | Maxwellian-averaged cross section |
| `resonance_integral` | Resonance integral |
| `resonance_spacing` | Average resonance spacing |
| `resonance_parameter/<parameter>/<modifier>` | Pointwise resonance parameters |
| `gamma_gamma` | Average radiative width |
| `strength_function` | Neutron strength function |
| `level_density` | Level-density parameter |
| `transmission` | Transmission data |

Not every projectile, target, or reaction has every observable. The directory
tree reflects data present in EXFOR and accepted by the parser's
observable-specific selection rules.

## File format

### Pointwise tables

A typical pointwise filename combines the target, reaction, optional residual
or incident-energy slice, first author, EXFOR entry/subentry/pointer, and
publication year:

```text
n/Al-27/n-inl-L1/xs/
  Al-27_n-inl-L1_Al-27_E.Almen-Ramstrom-20788-002-0-1975.txt
```

Its comment header records enough context to trace and interpret the data:

```text
# Header:
#   Title: 13-AL-27(N,INL)  Cross section
#   Source: EXFOR
# Target:
#   Z: 13
#   A: 27
#   Nuclide: 13-AL-27
# Reaction:
#   Process: N,INL
#   MF-MT number: 3 - 51.0
# Residual:
#   Nuclide: 13-AL-27
# EXFOR BIB:
#   Entry id: 20788-002-0 (entry-subentry-pointer)
#   Reaction code: (13-AL-27(N,INL)13-AL-27,PAR,SIG)
#   First author: E.Almen-Ramstrom
#   Master file: https://github.com/IAEA-NDS/exfor_master/blob/main/exforall/207/20788.x4
#   nds: https://nds.iaea.org/EXFOR/20788
#
#   E_in_lab(MeV)    dE_in_lab(MeV)    data(B)    ddata(B)
        2.0200E+00        0.0000E+00  8.0000E-02  1.2000E-02
```

For a standard pointwise table:

- column 1 is the independent variable `x`;
- column 2 is its absolute uncertainty `dx`;
- column 3 is the measured value `y`;
- column 4 is its absolute uncertainty `dy`.

The actual headings and units are written immediately above the values. They
depend on the observable and may include laboratory or centre-of-mass frame
suffixes. Missing numeric values in wider observable-specific tables are
written as `NAN`.

### Summary and resonance tables

Thermal, MACS, resonance-integral, average-spacing, strength-function,
gamma-width, and level-density files collect comparable results for a target
and reaction. Their columns can include EXFOR ID, author, year, incident
energy, value, uncertainty, and EXFOR modifiers.

Pointwise resonance-parameter files may additionally contain resonance energy,
spin, orbital angular momentum, and several reaction widths with their
uncertainties. Always use the column header in the selected file rather than
assuming it has four columns.

## Reading a pointwise table in Python

Comment lines begin with `#`, so NumPy can read the numeric block directly:

```python
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np

path = Path(
    "n/Al-27/n-inl-L1/xs/"
    "Al-27_n-inl-L1_Al-27_E.Almen-Ramstrom-20788-002-0-1975.txt"
)

x, dx, y, dy = np.loadtxt(path, comments="#", unpack=True)

fig, ax = plt.subplots()
ax.errorbar(x, y, xerr=dx, yerr=dy, fmt="o")
ax.set(
    xlabel="Incident energy [MeV]",
    ylabel="Cross section [b]",
)
fig.tight_layout()
plt.show()
```

Inspect the final commented header line before assigning physical labels,
because axes and units vary between observables.

## Online access

### Data Explorer

The [IAEA Nuclear Reaction Data Explorer](https://nds.iaea.org/dataexplorer/)
uses these observable-based datasets for plotting and file downloads. It
supports cross sections, residual production, angular and energy
distributions, double-differential data, fission yields, thermal and resonance
quantities, transmission, and other EXFOR-derived observables.

Search results retain the EXFOR entry/subentry/pointer identifier so that every
plotted dataset can be traced back to its entry page, JSON record, and original
master file.

### REST API

The production Reactions API is:

```text
https://nds.iaea.org/dataexplorer/api/reactions/<observable>
```

Common observable endpoint names include `xs`, `residual`, `fy`, `thermal`,
`macs`, `ri`, `da`, `de`, `ddx`, `transmission`, `d0`, `d1`, `s0`,
`s1`, `gg0`, `gg1`, and `rad`.

For example:

```sh
curl "https://nds.iaea.org/dataexplorer/api/reactions/xs?target_elem=Zr&target_mass=90&reaction=n%2Cg&table=true&page=1"
```

With `table=true`, matching pointwise tables are included in the API response.
Responses and Data Explorer downloads also provide links to the corresponding
files in this repository where applicable.

See the
[online Reactions API manual](https://nds.iaea.org/dataexplorer/docs/reactions-api)
and [OpenAPI documentation](https://nds.iaea.org/dataexplorer/docs/swagger) for
supported endpoints, filters, pagination, and response formats.

## Producing the datasets

Generation is implemented in `exforparser`. After configuring its EXFOR
master, JSON, database, and output paths, initialize and populate the parser's
SQLite database:

```sh
exforparser --init
exforparser --tabulate all
```

Then write all configured observable outputs:

```sh
exforparser --observables all
```

Individual output families can be regenerated with values such as `xs`,
`ion`, `angle`, `energy`, `ddx`, `fy`, `neutrons`, `thermal`, `macs`,
`resonance_integral`, `resonance_parameter`, `resonance_spacing`,
`gamma_gamma`, `strength_function`, `level_density`, or `transmission`.
See the current
[exforparser command-line implementation](https://github.com/IAEA-NDS/exforparser/blob/dev/src/exforparser/main_cli.py)
for the complete list and the distinction between pure-EXFOR and legacy
comparison outputs.

Parser behavior belongs in `exforparser`; this repository contains the
generated datasets.
